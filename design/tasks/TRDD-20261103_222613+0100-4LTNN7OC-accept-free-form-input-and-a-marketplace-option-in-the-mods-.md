- Source forms (same chapter :222-233): GitHub owner/repo with optional #ref; full git clone URL with optional #ref (https:// or git@host:path); a local directory holding .claude-plugin/marketplace.json, or that JSON file; an https URL of a hosted marketplace.json (relative plugin sources inside it do not resolve). A relative local path must start with ./ or ../; a bare name/name is GitHub.
- `claude plugin marketplace list --json`: local entries are {name, source:"directory", path, installLocation} with NO repo key; git entries carry url; github entries carry repo. The current step 2 ("an entry whose repo is null matches by name only") meets an absent key: fix it.
- Tests: PLUGIN_TOOL_SKILLS in tests/test_plugin_structure.py:45 and tests/test_skills_menu.py:227; test_skills_menu.py:737-746 parses allowed-tools with .split(",") and requires the run tool, reload-plugins, --force and the exact FAILED line; test_skill_to_mod.py:118 runs check_skill.py on this skill. No test pins the argument forms.

Design:
1. Input: free-form. Claude extracts the plugin name and, when present, a plugin repository and a marketplace source. Examples: `jr-polish@claude-code-mods`, `jr-polish from claude-code-mods`, `jr-polish --marketplace ~/Code/my-marketplace`, `owner/plugin-repo owner/marketplace-repo`, an https repository URL. Ask once if unclear; if still unclear, stop. New contract, stated in the skill: every value reaching the shell matches a strict pattern (plugin name ^[A-Za-z0-9][A-Za-z0-9._-]*$, owner/repo, https:// or git@ URL, absolute path) and is single-quoted; a value with ', a newline, or starting with - is refused.
2. `--marketplace <source>`: its value runs to the next known token; a path with spaces must be quoted by the user. Classify in this order: starts with /, ./, ../ or ~ = path (replace ~ with $HOME, resolve to an absolute real path, then `test -f '<abs>/.claude-plugin/marketplace.json'` or the path is that file); else https:// or git@ = URL; else owner/repo pattern = GitHub; else refuse. A folder with .claude-plugin/plugin.json and no marketplace.json: say it is a plugin, not a marketplace, and point to `claude --plugin-dir <folder>` for a one-off try.
3. Collision: before installing with --marketplace, read `claude plugin marketplace list --json`. Match local entries by resolved real path (path field; ~/Code is a symlink on some machines), git entries by url, github entries by repo. If an entry has the same name as the source's marketplace.json name but a different source, stop and ask; never replace a marketplace without a yes.
4. Install: with --marketplace, `claude plugin install '<name>' --marketplace '<source>' --json` (no -y), then the existing shownCommand + sha256 confirmation and -y rerun. Without it, the existing steps 2-4 (with the absent-repo fix). Step 5 reload unchanged.
5. Frontmatter: update description to the new forms; keep user-invocable true. Decide disable-model-invocation explicitly (recommend true: a permissive installer the model invokes on its own is a risk). Scope allowed-tools from bare Bash to exact claude plugin rules, kept as a comma string (the .split(",") test), no commas inside a rule; mods-uninstall-mod stays as is (note the asymmetry).
6. Tests that can fail: a live probe per input form (pluginId and source resolved), and the collision case (must stop and ask), in an isolated config (throwaway CLAUDE_CONFIG_DIR with auth reaching it, or the kit's sandbox); never the owner's real config. Check the probe harness first (recent probes wrote no transcript). Desktop: unverified until live-checked. One README line.

## Review revisions (supersede the design where they differ)

(a) NPT probe, isolated config, before the build: what native `claude plugin install --marketplace` does on a same-name different-source collision (refuse, reuse, or overwrite), and whether `--json` still prints shownCommand.
(b) Resolve the marketplace name before any install. Local path: read the name in `.claude-plugin/marketplace.json`. Remote source: run `claude plugin marketplace add '<source>' --json` first, read the name it reports, and compare it with the list taken before. On a clash, stop and ask. If the probe shows that native `--marketplace` reuses by name, route every `--marketplace` through `marketplace add` plus `install '<name>@<mkt>'`.
(c) The `--marketplace` value is one shell-style word: a path with spaces must be quoted.
(d) Accept an optional `#ref` (`[A-Za-z0-9._/-]+`) on owner/repo and git URLs. Give exact patterns for `https://` and `git@host:path`; refuse spaces or `'` in them.
(e) `disable-model-invocation` is an OWNER QUESTION, not decided: today Claude can install a mod when asked in plain words.
(f) Scoping allowed-tools is its own increment and commit: exact per-subcommand rules in the comma string. The -y rerun is not covered by a wildcard grant, so it prompts.
(g) Release 0.6.3 is inferred from the owner's request arriving mid-0.6.3, not confirmed.
