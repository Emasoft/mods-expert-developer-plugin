## Owner directive (verbatim, 2026-10-31)

"Also improve the mod-manager with a nicer panel and add the option of saving and loading profiles, that is a preset of enabled and disabled mods that the user can create from the current state, save in a mods-profiles.json file in the ~/.claude/.mod-manager/ folder, give it an unique name, and restore it anytime from the mod-manager to reconfigure the current user-scoped set of mods enabled. note that it only enable or disable mods already installed, it does not install them. if a mod is uninstalled or not found, the enable/disable setting for it is still preserved into the profile, but it is just not applied because the plugin was not found. if it is reinstalled, the mod-manager will automatically re-apply the profile setting to that plugin as soon as it is executed. the user can create many profiles and can apply any profile at any time. the profiles browser must list the profile names with a explanation of two lines of text that will explain what it does and how to create profiles. a `DUPLICATE PROFILE`, button will be shown in the top toolbar (always visible), and, if the user clicks on it, a sub panel will open where the profile content will be shown (the list of all mods enabled or disabled) and some buttons in the toolbar above (always visible even while scrolling)will allow to do something with it. The buttons are:`RENAME PROFILE` (it will check for name collisions while typing the new name in a input field, `DELETE PROFILE` (in red, asking confirmation), `APPLY PROFILE` (it will trigger /reload-plugins after the changes, but it will compact first since the reload plugins command invalidate the cache) and `EDIT PROFILE`. edit profile will make checkboxes to appear next to each mod in the profile list so the user can enable/disable each one. the button `EDIT PROFILE` will be renamed temporary to `SAVE CHANGES`, and only after clicking the button the changes will be saved to the profile. any other button will cancel the changes and restore the original profile configuration, exiting the edit mode. The total number of installed mods will be shown, as well as the total number of plugins (including those without mod code inside). optionally the user can click to a switch/checkbox that will change a label from `list only mods` to `list all plugins`. Profiles can in fact include the normal plugins state in them, with the ensble/disable state configuration of each plugin at user scope (project scoped plugins or local scoped plugins are not included in profiles, those only manage the user scope installed plugins)."

## Interpretations (INFERRED, open to the owner's correction; work proceeds on them)

1. DUPLICATE PROFILE copies the selected profile under a new unique name and opens the copy's sub panel. A NEW PROFILE action in the same always-visible toolbar saves the current user-scope state as a profile ("create from the current state"). Clicking a profile name in the browser opens its sub panel too.
2. Only plugins at scope user are recorded and applied (not project, local, managed, session or synced). An entry is keyed by its plugin id, name@marketplace, and records enabled true or false and whether the plugin has mod code.
3. Re-apply on reinstall: the store keeps the last applied profile and the entries that could not be applied because the plugin was not installed. On every mod-manager start and refresh, a pending entry whose plugin is now installed at user scope is applied and dropped from the pending list. Applying a profile replaces the pending list. Manual changes to plugins that were applied are never overridden.
4. APPLY PROFILE runs claude plugin enable or disable <id> --scope user only for entries whose state differs, then compacts, then runs /reload-plugins. How a mod sends /compact and /reload-plugins is settled from the mods docs and this plugin's self-command code; anything not documented is marked UNVERIFIED.
5. ~/.claude/.mod-manager/mods-profiles.json is written atomically (temporary file then rename), mode 0600, with a schema version field. Names are unique case-insensitively.
6. In edit mode any button other than SAVE CHANGES discards the edits and leaves edit mode. DELETE PROFILE is red and asks for confirmation. Buttons stay bracketed (house convention).
